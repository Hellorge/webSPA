Quickstart

Five minutes from git clone to a baked, running site. No frameworks. No package manager. Just Go, a templates folder, and a few HTML files.

1. Clone and build

Gogogo is a single Go module. The build CLI walks your web/ tree and writes a manifest the runtime mmap's into place. 

# in your project root
go mod tidy
go build ./cmd/build
go build ./cmd/main

2. Add a page

Make a directory under web/main/content/. Drop a content.html. The three engine directives (extends, alias, hole) live inline; everything else is stdlib text/template syntax. 

<!-- web/main/content/news/content.html -->
{% extends "def" %}
{% alias "/news" %}

{{ define "head" }}
<title>Latest news</title>
{{ end }}

{{ define "content" }}
<h1>Latest</h1>
<ul>
  {% hole "SELECT title, summary FROM news ORDER BY date DESC" %}
    <li><b>{{ .title }}</b> {{ .summary }}</li>
  {% endhole %}
</ul>
{{ end }}

Convention. Each page is its own directory. content.html is the only required file. Sibling style.css and script.js get auto-discovered and linked in. The alias defaults to the directory name; {% alias %} overrides when you need something else (like "/").

3. Build it

./build -force # first run; later runs are incremental

Build walks every [[site]] in web/config.toml and writes a manifest per site: 

[main] Starting build...
Gogogo V4 [main]: 17 routes (1 with holes, 0 disk-served)
Gogogo V4 [docs]: 8 routes (2 with holes, 1 disk-served)

4. Serve it

./main # spawns SO_REUSEPORT bouncers, one per CPU

Visit http://localhost:8082/news — the page is served from a brotli-compressed payload baked into the manifest, with the recent hole spliced from a fresh SQL query.

5. Edit, hot-reload, ship

Rebuild with ./build, then send SIGHUP to the server. The new manifest swaps in atomically; in-flight requests finish against the old one. 

./build
kill -HUP $(pgrep main)
