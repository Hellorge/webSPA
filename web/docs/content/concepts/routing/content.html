Routing

One trie walks every request. Literal segments, captured params, catch-all suffixes — the same lookup, the same matcher, the same dispatch path. URL bindings reach your page templates the same way SQL row data does.

Pattern syntax

"/api/users"          // literal — matches exactly /api/users
"/api/users/:id"      // :name captures one segment as a binding
"/static/*path"       // *name captures the rest (must be terminal)

You declare the pattern as the page's alias. Build registers it in the trie; nothing else changes about how you author the page. 

<!-- web/main/content/user_profile/content.html -->
{% extends "def" %}
{% alias "/users/:id" %}

<h1>User {{ ._params.id }}</h1>

Same page, same template, different URLs — same engine handling each:

Literal route

The simplest case. URL matches exactly, nothing captured.

  • /concepts/holes — this doc page itself
  • /quickstart

Param route (:name)

Captures exactly one URL segment. Click any of these — same underlying file, different binding:

  • /playground/about  →  section = "about"
  • /playground/users  →  section = "users"
  • /playground/anything-you-want  →  section = "anything-you-want"

Catch-all route (*name)

Captures one OR more segments, joined with slashes. Must be the last element in the pattern.

  • /catchall/single  →  rest = "single"
  • /catchall/files/2024/report.pdf  →  rest = "files/2024/report.pdf"
  • /catchall/a/b/c/d/e  →  rest = "a/b/c/d/e"

Precedence on overlap

At any trie node, children can be literal, a single :param, and a single *catchall. Match order: literal > param > catch-all. 

// these three coexist as siblings at the same parent
"/x/foo"      // literal — wins for /x/foo
"/x/:p"       // param   — wins for /x/bar (p = "bar")
"/x/*all"     // catch-all — wins for /x/a/b/c (all = "a/b/c")

Mixing literal and dynamic siblings is legal — /users/me and /users/:id can both exist; the literal wins for /users/me, the param catches everything else.

Reaching bindings inside your page

Captured params appear under the special key _params in every hole body. The underscore prefix is reserved so SQL column names can't collide. Two ways to use it:

1. As a no-DB hole (empty SQL)

A {% hole "" %} block runs its template once with just the URL bindings — no DB call. Useful for pure URL-derived content (an API echo, a profile header, anything that doesn't need SQL). 

{% hole "" %}
<h1>User {{ ._params.id }}</h1>
{% endhole %}

2. Mixed with SQL

Inside a normal SQL hole, both {{ .column }} and {{ ._params.id }} work. SQL row columns and URL bindings live in the same template context. 

{% hole "SELECT name FROM users WHERE id = 1" %}
<h1>{{ .name }}</h1>
<p>profile id: {{ ._params.id }}</p>
{% endhole %}

Method dispatch

Each route declares the HTTP methods it accepts (comma-separated; default is GET). Declaring GET implicitly enables HEAD. A request whose method isn't allowed gets 405 Method Not Allowed with a pre-baked Allow: header. 

{Path: "api/posts",     Method: "GET",         ActionID: ListPosts}
{Path: "api/posts",     Method: "POST",        ActionID: CreatePost}
{Path: "api/posts/:id", Method: "GET, PATCH, DELETE", ActionID: PostByID}

Try it: studio's /sql endpoint is POST-only. Send GET and the engine returns 405 with Allow: POST. 

$ curl -i -H 'Host: studio.localhost' http://localhost:8082/sql
HTTP/1.1 405 Method Not Allowed
Server: Gogogo
Allow: POST
Content-Type: text/plain; charset=utf-8

Special conditions and caveats

  • Catch-all must be terminal. /a/*b/c is invalid — once you start catching the rest, you can't put literal segments after.
  • One catch-all per pattern. /a/*b/*c is invalid; everything after the first * goes into that one binding.
  • Param/catch-all routes cache by (route, bindings). The cache key includes a hash of the URL bindings, so /users/1 and /users/2 become separate entries. Hot URLs serve from cache at static-page QPS; one-shot URLs (per-session UUIDs etc.) LRU-evict and effectively render fresh. No per-installation tuning.
  • Param names must be consistent at a depth. You can't have /users/:id and /users/:slug coexist — the build rejects it. Pick one name per node.
  • Bindings are strings. No type coercion; _params.id is the raw URL segment as captured. Convert in your SQL or template as needed.
  • Empty catch-alls don't match. /catchall/*rest requires at least one segment after /catchall/; bare /catchall won't match. Add a literal sibling if you need that case.

Why it's fast

  • Depth is bounded. Real URLs have 3–5 segments. The trie's O(depth) is effectively O(1).
  • Each step is one hash + one map probe. ~30 ns per segment.
  • Method check is a bitmask AND. One cycle.
  • 405 responses use a pre-baked head. No format, no string allocation.
  • Static and dynamic share the same path. One flow, one branch predictor target, one mental model.
