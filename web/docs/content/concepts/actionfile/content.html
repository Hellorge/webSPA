ActionFile

Files past a configurable size threshold skip the manifest and serve via sendfile(2). Range-aware. HEAD-aware. Bytes go kernel→kernel without ever touching userspace.

How the build decides

Each file under web/<site>/static/ goes through type-dispatch. CSS gets minified. JS gets minified. HTML always embeds in the manifest because templates need processing. Everything else, if it's at or above -embed-threshold (1 MiB by default), is promoted to an ActionFile route.

ExtensionBehavior
.htmlAlways embed. Template processing required.
.css / .jsMinify, then embed.
everything elseBelow threshold → embed. At/above → ActionFile.

The route blob

An ActionFile route doesn't have payload bytes in the manifest. Instead its HoleOffset points at a small blob: 

// stored in the manifest's HoleBlobs region
[pathLen: u16] [path: N bytes]

Where path is the disk path the runtime opens. The build writes the actual bytes to dist/<site>/<relPath> so two sites can have files with the same relative path without collision.

The runtime path

func serveFile(req, resp, entry, manifest, st) {
    file := os.Open(readFileBlob(...))
    heads := st.fileHeads[mimeForFile(path)]

    if hasRange(req) {
        resp.HeadID = heads.head206
        resp.SetContentRange(start, end, fi.Size())
        resp.Stream = func(w io.Writer) error {
            defer file.Close()
            _, err := io.CopyN(w, file, length)
            return err
        }
        return
    }

    resp.HeadID = heads.head200
    resp.Stream = func(w io.Writer) error {
        defer file.Close()
        _, err := io.Copy(w, file)
        return err
    }
}

On Linux, Go's runtime promotes io.Copy(*TCPConn, *os.File) into a sendfile(2) syscall. The bytes never visit the Go heap. The CPU isn't doing copies; the kernel is.

Heads are pre-baked too

When the server loads a manifest, it walks every ActionFile route and pre-registers two HTTP heads per mime type: one for 200 OK and one for 206 Partial Content. Both bake Accept-Ranges: bytes. At request time, picking the right head is a map lookup; the bytes go straight to the wire.
